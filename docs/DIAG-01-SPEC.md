# Bey-Lab DIAG-01 標準診断仕様

## 目的
1on1・3on3などの各ページで、ユーザーが何を操作し、アプリ内部で何が起きたかを自動記録し、不具合の調査に使う。

## UI
- 画面に常時表示する「🔬 操作診断 v1」パネル。右上に `DIAG-01`。
- 時刻付きログを新しい順に表示する。参考実装は `lab-migration.html` の `installOneOnOneDiagnostics`。
- 診断用のボタン、タップカウンター、開閉操作は付けない。
- 操作の邪魔をしない配置とし、動的に再描画される領域の内側には置かない。

## 自動記録
- `① TAP`: 操作した対象、側、部品、値
- `② STATE`: 操作時点の状態（試合・得点・選択・編成など、ページに応じて）
- `③ SAVE OK` / `SAVE ERROR`: 保存処理の結果
- `④ RENDER`: 画面描画の実行
- `⑤ RESULT`: 操作後の状態
- `✖ ERROR` / `✖ REJECT`: JavaScriptエラー、未処理Promise拒否
- 起動時の `READY` と必要な状態変化のログ

## 実装上の注意
- 診断は観測専用。既存の試合ロジックや保存データを変更しない。
- ログ出力でアプリを止めない。診断のエラーも可能な範囲で記録する。
- 起動エラーも拾えるよう、可能ならアプリ初期化より前にエラー監視を設定する。
- 1on1と3on3では画面固有の操作・状態を適切に記録する。
- 3on3に導入するときは、先に既存の操作・保存・描画処理を調べ、最小限の変更で接続する。いきなり全面改修しない。
- 最初はログを一時保持する方式でよい。再読み込み後にも残す場合は別途合意する。
