## 目的と表示
- 不具合発生時に「操作が届いたか／処理前後で何が変わったか／保存されたか／描画されたか／なぜ失敗したか」を追えること。
- 「🔬 操作診断 v1」＋右上 `DIAG-01` のパネルを画面の下部に常時配置。勝ち抜きでは**大会履歴の下**。3on3でも主操作の邪魔にならない、再描画で消えない位置に置く。
- **操作不要の自動ログ。** 診断用ボタン、タップカウンター、手動更新・開閉ボタンは不要。
- ログは時刻付き、新しい順、**実際の改行**で表示する。直近60件を表示し、長いログはパネル内でスクロール可能にする。

## 最新ログ形式
- `READY`：起動、環境、登録データ・依存関係の確認。
- `#番号 ① ACTION`：クリック／選択変更の対象、B/X側、部品や値。すべての操作を捕捉する。
- `#番号 ② BEFORE`：操作直前の状態。
- `③ SAVE OK / ✖ SAVE ERROR`：実際の保存処理の成功・失敗。保存しなかった場合は `not attempted`。
- `④ RENDER`：画面再描画の実行。
- `#番号 ⑤ AFTER`：操作後の状態と `changed=YES/NO`、`save=OK/ERROR/not attempted`。
- `NOTICE`：バリデーションの警告や操作結果の通知。
- `✖ VALIDATE FAILED`：操作を拒否した理由。可能なら該当状態も記録。
- `✖ ERROR`、`✖ REJECT`：JavaScript例外・未処理Promise拒否。
- **注意:** `changed=NO` は異常とは限らない。画面の開閉など、記録対象の状態が変わらない正常操作がある。3on3では画面の開閉・編成・選択なども必要に応じて状態に含める。
- **注意:** 操作番号ごとの保存結果が他操作と混ざらないように管理すること。単一の共有変数だけで判定すると、操作が連続した場合に誤表示する可能性がある。

## 3on3で追跡する状態
- 対戦中のB/Xプレイヤー、各3機の編成・順番・公開/非公開・現在の対戦機体。
- 各ラウンドの勝敗・フィニッシュ種別・得点・合計点、勝者、試合の進行状態。
- 保存キーと保存結果、再描画、エラー。
- 記録対象は実装済みの実際の状態に合わせる。機密情報や端末固有情報を無駄に記録しない。

## 安全な実装手順
1. `league.html` のイベント処理、状態管理、保存キー、描画箇所を調べる。
2. 診断パネルとログ収集を追加し、既存の勝敗ロジック・保存データ・名簿を変更しない。
3. すべてのボタン・選択操作を拾い、保存・描画・警告をそれぞれ実処理から記録する。**タップだけで成功と判定しない。**
4. GitHubへ保存したら読み直し、実機で複数操作を試し、スクリーンショットのログで確認する。
