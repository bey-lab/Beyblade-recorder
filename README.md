# BEY LAB — Beyblade X battle recorder

スマホ・iPadで使える、ローカル保存のベイブレードX対戦記録アプリ。GitHub Pages 上で公開。

- **従来版**: https://bey-lab.github.io/Beyblade-recorder/ (`index.html`)
- **新・横画面アリーナ β版**: https://bey-lab.github.io/Beyblade-recorder/arena.html (`arena.html`)

## 目指すもの

**「その場ではスコアボード、あとで研究所。」**

主な遊び方は、3人で2〜3時間続くテンポの速い勝ち抜きバトル。その場で「王」（勝者）と挑戦者が戦い、もう1人は次に使うブレードとカスタムを考えている。全員が遊びに集中していて専属の記録係はいない。アプリのせいで遊びを止めないことが最優先。

締めくくりには3人の3on3総当たり戦を行うこともある。ここは将来の機能候補。

## 現行実装

### `index.html` — 従来の実験・分析アプリ

- 機体・カスタム登録、対戦相手入力、勝敗とフィニッシュ種別記録
- 分析、履歴、JSONバックアップ/復元、CSV書き出し
- `localStorage` キー `bey-lab-recorder-v1`
- **この保存データ・既存機能を壊さないこと。**

### `arena.html` — 横画面対戦ボード（2026-10-14 初回追加）

- **B-SIDE / X-SIDE** 対戦レイアウト、中央スコア、左右入れ替え
- 登録済みプレイヤーとブレードの選択肢を最初から表示し、試合中に即タップで切り替え
- 名簿の追加、改名、上下移動による並び替え（⚙ 登録・並べ替え）
- B/Xそれぞれに対し、スピン1・オーバー2・バースト2・エクストリーム3点のフィニッシュをワンタップで記録
- **4点以上で自動的に勝者を宣言**、勝利画面の「次のバトルへ」ボタンで現対戦を保存し、得点を0-0にして続行。勝利画面から直前の得点を取り消し可能
- 大会開始時に**日付とタイトルを指定する導入画面**。大会ごとに固有IDを付け、別の日の対戦と分離して履歴表示。タイトルは対戦画面に常時表示
- **本日の最長連勝**を上部に表示。同一大会内で同じプレイヤーが続けて4点先取した試合の連勝数で計算。正式な王座防衛モードとは別
- スコア手動増減、直前の操作の取り消し、登録名の削除（履歴は保持）、履歴表示、JSON/CSV書き出し（大会日付・タイトル付き）
- `localStorage` キー `bey-lab-arena-v1` に**別保存**。旧データとは混ぜない
- 新規のサンプル選手名は **プレイヤー1/2/3**、初期ブレード名は **ドランソード/ヘルズサイズ/ウィザードアロー/ナイトシールド**。ユーザー名は公開コードに含めない
- 以前のβ版で試合記録のない未変更サンプル選手リストに限り、旧サンプル名を汎用名へ移行。試合記録・カスタマイズ済みの名簿は変更しない
- ブレード名は任意の名前で登録。初回のみ従来版の登録済み機体からブレード候補を簡易取り込み
- β版では**キングの自動交代、勝ち抜きモードの本格進行、3on3リーグ、分析への統合、JSON復元は未実装**。4点先取の自動勝利宣言と大会別の連勝集計は実装済み。現在のアリーナは手動スコアボード中心
- 横画面推奨。iOS Safari / PWAでは端末の画面回転をWebアプリから必ずしも強制できないため、縦画面時は横スクロール可能にする

## UIデザインの意図

- 格闘ゲームのVS画面のような**赤B・青Xの対決感、中央巨大スコア、発光アクセント**
- ただし試合中の操作は爆速で、入力フォームや深いメニューを増やさない
- プレイヤー名・ブレード名とも自由登録。よく使う項目を並び替えて近くに配置
- 左右のB/Xは端末の置き方で変わるので簡単に入れ替え可能
- ブレードの専用イラスト画像や演出は初回β版では未実装。後日ユーザーと確認して追加検討
- 変更・テスト時は既存の対戦記録が残ることを優先し、破壊的データ移行を避ける
- ボタン連打がiOSでダブルタップズームになる問題への対応として `touch-action: manipulation` を操作要素とHTML全体に設定。ピンチズームは意図的に無効化しない

## 技術

ビルドツール不要の静的HTML/CSS/JavaScript。GitHub Pages は `main` の root。オフラインキャッシュは `sw.js`（更新時はキャッシュキーのバージョンを変更）。`manifest.webmanifest` がPWA設定。

注意: GitHub Pages とコードは公開される。端末内のローカル記録は自動的には端末間同期しない。Safariとホーム画面アプリは保存領域が異なる場合がある。

## iPad Pro対応（2026-10-14）

`arena.html`に横画面タブレット向けレイアウトを追加。900px以上の横幅かつ600px以上の高さではプレイヤー・ブレード選択ボタンを大きくし、両サイドのフィニッシュボタンをそれぞれの下に配置する。左/右それぞれから操作できるよう、選択ボタンは常時表示。iPad Pro 13インチ横向きの実機確認はユーザーによるテスト待ち。変更時には`sw.js`のキャッシュバージョンも更新すること。

## 4点勝利と削除（2026-10-14）

- B/Xの一方が4点以上になった瞬間、勝者のプレイヤー名・ブレード名・得点を全画面に表示し入力をロック。「次のバトルへ」で試合の明細と勝者を`sessions`へ保存してスコアリセット。リスト選択状態は維持。
- 勝利画面から直前得点を取り消し可能。通常の「＋新しい対戦」でも途中試合を履歴保存できる。
- プレイヤー・ブレードの登録名に削除ボタンを追加。最後の1件は削除不可、使用中の項目を消したら残存リストの先頭に切り替え。記録済みイベントは削除しない。
- この更新の初期構文解析および模擬DOMによる得点/勝利/次試合/削除/保存の単体チェックはパス。Safari実機の操作確認はこれから。

## 大会の日付・タイトル・最高連勝と連打対策（2026-10-14）

- `meetings: [{id,date,title,created}]`, `activeMeetingId` をアリーナの既存localStorage状態に後方互換で追加。`sessions`（旧称：対戦ごとの完了履歴）は残して各対戦に `meetingId`, `meetingDate`, `meetingTitle` を付与する。**以前の記録に日付・大会名を勝手に割り当てない**。
- 初回/未設定では大会作成フォームを出さず、自動で日付のみの大会を作る。タイトルは後から任意で設定し、保存済みの試合も同じ大会IDのまま更新。新大会への切り替え時、前の進行中の対戦は旧大会へ保存。保存済みリストのプレイヤー/ブレードは維持。
- 履歴は大会IDごとにグループ化。「以前の記録（大会未設定）」として旧データも残す。CSVに日付/タイトルを追加。
- `longestStreak()` は同一大会IDの保存済み完了試合を順番に走査し、今まさに勝利画面が出ている進行中の勝者も数える。勝者不明の途中終了が入ると連勝が途切れる。同率なら双方表示。他大会は混ぜない。
- `touch-action: manipulation` によりタッチ操作でのSafariダブルタップズームを抑制する。動作は端末/iOSに左右されるので実機テスト待ち。画面全体の拡大を禁止する `user-scalable=no` は使用しない。
- モックDOM上で大会作成、複数大会の分離、勝利/保存、最高連勝、再読み込み、履歴表示の基本テスト成功。Safari/iPad実機の動作はまだ未確認。

### 長期保存上の注意

大会の終了試合を200件で自動削除していた旧仕様を廃止し、昔の大会履歴を黙って削除しない。ただしブラウザの`localStorage`には保存容量の上限があるため、履歴画面から**JSONバックアップを定期的にダウンロード**すること。JSONからの復元機能は今後の開発課題。

## 対戦中の操作スピード改善（2026-10-15）

ユーザーの実機スクリーンショットとプレイ感想を受け、`arena.html`を再設計。

- **起動時に大会作成フォームを強制しない。** その場のローカル日付から無題の大会を自動作成して即対戦画面に入る。既存の大会名・履歴は保持。アプリを別の日に開いた場合は原則として新しい日付の大会を自動作成して履歴を分離し、途中のスコアがあれば旧大会へ未完了として保存する。ユーザーが手動で別日を設定した大会は勝手に日付を上書きしない。
- ヘッダーの **「大会名・日付」** から日付やタイトルを後付け・編集できる。タイトルは空欄でOK。すでに保存された同じ大会の試合履歴のタイトル・日付も編集内容に追従。別大会を作りたいときは設定画面の **「＋ 別の大会を作る」** を押す。大会ごとの集計は固有IDで分離。
- 各サイドのファイターカード**内部に4つのフィニッシュボタンを配置**（スピン、オーバー、バースト、エクストリーム）。iPad横画面（CSS幅850px以上・高さ530px以上）では全体を画面高に収めるフレックスレイアウト。これにより勝敗入力に画面縦スクロールが不要になる設計。
- ブレード一覧を**2列グリッドに拡大**し、余白を一覧表示へ優先配分。左右それぞれから「▦ 全機体」でさらに広いグリッドを開き、検索絞り込みと選択ができる。試合画面での選択は直接ワンタップ。
- タップ後のファイターカード再描画でもプレイヤー/ブレードのスクロール位置を維持するようにした。
- 従来の`localStorage`キー `bey-lab-arena-v1` を保持し、既存の名簿と対戦記録を破壊しない。従来版の記録データも触らない。
- ブラウザ実装に近いモックDOM上で23項目（大会を即開始、画面上の4種ボタン、全機体選択、フィルタリング、4点勝利、日付別履歴と後付けタイトル、リロード保存）の操作チェックを通過。**実機の横画面表示・スクロール挙動は引き続き確認が必要**。

### 注意
- 元のREADMEの「初回なら大会作成フォームを開く」は改訂済み。現在は**初回でも自動で日付ごとの大会を用意**し、タイトル入力なしでプレイ可能。
- 旧バージョンの大会名が日付そのものの場合、ヘッダーで日付が重複表示されないよう調整済み。

## 中央8ボタンのスコアボードと独立したブレード選択（2026-10-15）

iPad Pro横画面での勝敗操作が画面下方にはみ出すとの実機フィードバックから修正。

- **中央のスコア欄の真下に4行×2列の8フィニッシュボタン**を常時表示。各列の見出しはB/Xサイドと連動し、各フィニッシュ（スピン1点、オーバー2点、バースト2点、エクストリーム3点）をワンタップで記録。勝利は従来通り4点到達で自動宣言。
- 手動の点数修正は中央下部の「± 点数修正」内へ移し、誤タップしづらくした。プレイヤー別パネル内のフィニッシュボタンは廃止し、ブレード選択の縦領域を確保。
- B/X入れ替え時は、中央ボタンの左右と色も入れ替わる。入力は論理サイド（B/X）に紐付き、物理位置だけで誤記録しない。
- **全機体セレクターは物理左/右それぞれ画面幅の50%だけを使う独立した固定パネル**。両方同時に開けて、互いの操作を妨げない。「全機体」→該当する側の半画面表示→ブレード選択で自分のパネルだけ閉じる。フィルターも左右独立。
- パネルを開いている間、他方のブレード選択やフィルターは影響を受けない。端末を縦にした場合は各全画面へフォールバック。
- 画面高を優先するCSSを追加し、大きなスコアと8ボタン、左右ブレードリストの見える領域を調整。
- データ形式および`localStorage`の保存キーは従来から変更なし。21項目の模擬DOMテストで中央の8ボタン、色/BX入替、左右同時表示、各側だけ閉じる、4点勝利、次のバトル、保存と再読み込みを確認。**実機での画面はみ出しの最終確認は引き続きユーザーと行う。**

### 対戦テンポの基本方針
入力必須画面を作らず、試合中の全操作は大きいタップ領域にまとめる。格闘ゲーム風の出撃演出はブレード選択パネルに持たせ、中央は視認性・速さ優先のスコアボードにする。
